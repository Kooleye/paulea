# Запуск на Timeweb

Это приложение — обычный сервер на Node.js без зависимостей. Запуск всегда один и тот же:

```
node server.js
```

Ниже — как поднять его на **Timeweb Cloud → Приложения (Backend / Node.js)**. Это самый простой способ.

## 1. Создать приложение

1. Зайдите в панель Timeweb Cloud → **Приложения** → **Создать**.
2. Тип приложения: **Node.js** (Backend).
3. Источник: загрузите этот архив (или подключите Git-репозиторий, если используете его).
4. Версия Node.js: **18 или новее** (важно — на старых версиях не работает встроенный `fetch`).

## 2. Команды сборки и запуска

- **Команда сборки (Build):** оставьте пустой или `npm install` (зависимостей нет, установка ничего не скачает).
- **Команда запуска (Run / Start):**
  ```
  npm start
  ```
  (это то же самое, что `node server.js`).

## 3. Порт

Ничего настраивать не нужно. Timeweb сам передаёт порт в переменной `PORT`, а сервер её читает.
Сервер слушает `0.0.0.0`, как и требует платформа.

## 4. Переменные окружения (Environment variables)

Задайте их в панели Timeweb (раздел «Переменные окружения»), НЕ храните секреты в коде:

| Переменная | Зачем | Пример |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather | `123456:AA...` |
| `TELEGRAM_MANAGER_CHAT_ID` | куда слать заявки (ваш id или id группы с минусом) | `-1001234567890` |
| `ADMIN_PASSWORD` | пароль от админки `/admin.html` | придумайте свой |
| `ALLOW_BROWSER` | на боевом сервере поставьте `false` | `false` |

Порт `PORT` задавать вручную не нужно — его выдаёт Timeweb.

## 5. Данные и загруженные фото — важно!

На App Platform («Приложения») контейнер при каждой пересборке создаётся заново из GitHub,
а постоянный диск подключить нельзя. Поэтому всё, что лежит на локальном диске
(файл `data/db.json`, папки `public/photos/` и `public/banners/`), **при пересборке теряется**.

Решение — хранить базу и фото в облачном **S3-хранилище Timeweb**. Код это уже умеет:
нужно только создать бакет и добавить переменные (см. раздел 7).

Если переменные S3 не заданы, всё работает из локальных файлов (удобно для тестов на компьютере),
но на App Platform данные не переживут пересборку.

## 6. Telegram Mini App

1. После деплоя Timeweb даст домен вида `https://ваш-проект.twc1.net`.
2. В @BotFather → **Bot Settings → Menu Button / Web App** укажите этот адрес (обязательно `https`).
3. Откройте бота — витрина откроется внутри Telegram.

## 7. Облачное хранилище S3 (чтобы фото и товары не пропадали)

Настраивается один раз. После этого база (`db.json`), фото товаров и баннеры хранятся в облаке
и переживают любые пересборки приложения.

1. В панели Timeweb Cloud → **Облачное хранилище (S3)** → **Создать**.
2. Тип доступа — **Приватный** (в базе есть телефоны клиентов, публичным делать нельзя).
   Картинки витрина отдаёт сама через свой сервер, так что приватный бакет — то, что нужно.
3. После создания откройте хранилище и найдите:
   - **имя бакета** (часто вида `abc12345-myshop`),
   - **адрес/endpoint** (обычно `https://s3.twcstorage.ru`),
   - **регион** (обычно `ru-1`),
   - **Access key** и **Secret key** (ключи доступа).
4. В настройках приложения (Переменные окружения) добавьте:

| Переменная | Значение |
| --- | --- |
| `S3_ENDPOINT` | `https://s3.twcstorage.ru` |
| `S3_REGION` | `ru-1` |
| `S3_BUCKET` | имя бакета из панели |
| `S3_ACCESS_KEY` | Access key |
| `S3_SECRET_KEY` | Secret key |

5. Сохраните и пересоберите приложение. В логах при старте должно появиться
   «☁️ Хранение файлов: облако S3».
6. Проверьте: загрузите фото товара через админку, затем нажмите «Пересобрать» —
   товар и фото останутся на месте.

## Альтернатива: обычный VDS Timeweb

Если берёте не «Приложение», а виртуальный сервер (VDS):

```bash
# установить Node.js 18+ (пример для Ubuntu)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# распаковать архив, зайти в папку проекта
cd paulea

# создать .env (см. .env.example) и запустить постоянно через pm2
sudo npm i -g pm2
pm2 start server.js --name paulea
pm2 save && pm2 startup
```

Чтобы сайт был доступен по `https` на 443 порту — поставьте перед приложением nginx как reverse-proxy
на `http://127.0.0.1:3000` и выпустите бесплатный сертификат Let's Encrypt.
